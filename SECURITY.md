# Безопасность сайта и админки

Коротко: сайт — статические файлы без сервера и базы, ломать там нечего. Единственная «дверь» — админка. Она устроена так, чтобы даже при неудаче на одном уровне следующий уровень остановил злоумышленника.

## Как устроено

```
Браузер админа ──https──► admin.permstandup.ru (API Gateway)
                               │
                               ▼
                    Yandex Cloud Function «admin»
                    • проверяет вход и права
                    • проверяет каждое поле
                    • пишет только в src/content и public/uploads
                               │  токен GitHub App (1 репозиторий, contents:write, 1 час)
                               ▼
                    GitHub: permstandup/site ──► GitHub Actions ──► сборка ──► Object Storage ──► permstandup.ru
```

- Админка живёт на **отдельном поддомене** `admin.permstandup.ru`. Публичный сайт и админка — разные «источники» для браузера: проблема на публичном сайте не даёт доступа к админке.
- Ключи от GitHub хранятся **только в функции** (переменные окружения Yandex Cloud). В браузер они не попадают никогда.

## Уровни защиты

| Угроза | Что защищает |
| --- | --- |
| Чужой человек входит в админку | Вход только через GitHub. Пускаем **только аккаунты из белого списка** (по неизменяемому числовому id) и **только с включённой двухфакторной защитой** (проверяется при каждом входе). |
| Подмена входа (OAuth) | Одноразовый `state` + PKCE (S256), cookie входа живёт 10 минут. Токен пользователя GitHub сразу отзывается, писать в репозиторий он не может. |
| Кража сессии | Cookie `__Host-sup_admin`: зашифрована AES-256-GCM, `HttpOnly` (JS её не видит), `Secure`, `SameSite=Strict`, только для admin-домена. Срок — 24 часа. Белый список проверяется на **каждом** запросе: убранный из списка теряет доступ сразу. Кнопка «Выйти на всех устройствах» обнуляет все сессии. |
| Действие от имени админа с чужого сайта (CSRF) | `SameSite=Strict` + проверка `Origin` + обязательный заголовок `X-Admin: 1` + только `application/json`. CORS не разрешён никому. |
| Вставка скрипта (XSS) | В админке все данные выводятся только как текст (без `innerHTML`). На сайте описания — обычный текст, не HTML/Markdown. Строгий CSP на админке (`script-src 'self'`, `frame-ancestors 'none'`) и на сайте (скрипты только по хэшам). |
| Опасные ссылки | Только `https://`; соцсети и видео — только с разрешённых доменов (t.me, vk, rutube, youtube); никаких `javascript:` и логинов в адресе. |
| Вредный файл под видом фото | Фото пересжимаются в браузере (заодно удаляются EXIF/GPS). Сервер принимает только настоящие JPEG/WebP по содержимому, до 2,5 МБ, имя файла придумывает сам. SVG/HTML отклоняются. |
| Подмена кода сайта через админку | Сервер пишет **только** в `src/content/*` и `public/uploads/*` по белому списку путей; имена — только `a-z0-9-`. Токен GitHub App не имеет права менять `.github/workflows`. Откат старой версии тоже проходит все текущие проверки. |
| Одновременные правки | Каждое сохранение указывает версию файла; если её кто-то изменил — ошибка «обновите страницу», а не тихая перезапись. |
| Перебор и спам | Ограничение частоты в функции (вход — 20 за 10 минут с адреса; изменения — 60 в минуту) и лимиты на API Gateway. |
| Встраивание админки в чужую страницу | `frame-ancestors 'none'`, `X-Frame-Options: DENY` и проверка в скрипте. |
| Уязвимости в библиотеках | Версии закреплены точно; новые версии — не младше 2 недель; `npm audit` = 0. |
| «Всё сломали» | Вся история в git: любую прошлую версию шоу/комика/фото/настроек можно вернуть из админки. Репозиторий — второй резервной копией у GitHub. |

Все входы, выходы и изменения пишутся в журнал Yandex Cloud Logging (кто, что, когда, с какого адреса). Пароли, токены и cookie в журнал не попадают.

## Тесты

`npm run admin:test` — 32 теста, каждый пытается провести атаку (поддельная cookie, чужой state, аккаунт без 2FA, CSRF, `../` в путях, `javascript:`-ссылки, SVG со скриптом, подмена YAML, правка кода сайта через откат и т. д.) и проверяет, что она не проходит.

## Что нужно соблюдать людям

1. **Двухфакторная защита** (приложение-аутентификатор) — на GitHub, у регистратора домена, в Яндекс ID и Yandex Cloud. Коды восстановления хранить офлайн.
2. Пароли, коды и ключи **никому не пересылать** — ни в мессенджерах, ни Claude.
3. Добавлять людей в админку только через настройку `ADMIN_GITHUB_USERS` в Yandex Cloud (из самой админки это невозможно специально).
4. Если ноутбук/телефон потерян — «Выйти на всех устройствах» в админке и смена пароля GitHub.
5. Если есть подозрение на утечку ключей — перевыпустить ключ GitHub App и `SESSION_KEY` (см. `admin/DEPLOY.md`).
